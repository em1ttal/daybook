# Internationalisation (i18n)

daybook is planned from the start to support several languages ([0008](../decisions/0008-multilingual.md)). **English (`en`) is the source language**, Spanish (`es`) is the second, and adding a language means **adding a folder**, with no code changes ([0012](../decisions/0012-locale-folders.md)). Built in M5 (foundation) and M6 (selector, all strings).

## Locale folders

```
locales/
├── en/
│   ├── messages.json
│   └── flag.svg
└── es/
    ├── messages.json
    └── flag.svg
```

- **The folder name is the language code** (BCP 47: `en`, `es`, `pt-BR`). Code needs the code for `<html lang>`, date formatting and the user's saved `locale`.
- **The name shown in the selector comes from the JSON**, written in the language itself, so a Spanish speaker finds "Español" even when the app is in English:
  ```json
  {
    "meta": { "name": "Español", "dir": "ltr" },
    "common": { "save": "Guardar", "cancel": "Cancelar" },
    "today": { "empty": "Nada pendiente para hoy" },
    "errors": { "task": { "not_found": "Esa tarea ya no existe" } }
  }
  ```
- **`flag.svg`** is shown next to the name. A flag stands for a country, not a language (Spain or Mexico? UK or US?), so it's a visual hint only. The text name is what screen readers announce.
- **`locales/` is at the repo root** so the web app, the server and the Apple apps share one source of truth.

## Web
- `vue-i18n` with messages loaded by key: `t('today.empty')`.
- **Discovery:** `import.meta.glob('@locales/*/messages.json')` lists every folder at build time. The selector is built from that list, and only the active language's file is downloaded. Vite needs an `@locales` alias and `server.fs.allow: ['..']` to read outside `web/`.
- **Choosing the language:** the user's saved `locale` → the browser's `navigator.languages` → `en`. `<html lang>` and `dir` are set to match.
- Missing keys fall back to `en` and log a warning in development.

## Rules for strings
- **Every user-facing string goes in the JSON**, including `aria-label`, `title`, `placeholder`, alt text and page titles.
- Keys are namespaced by feature: `auth.login.submit`, `calendar.views.week`.
- **Placeholders and plurals, never concatenation:** `"count": "No tasks | One task | {n} tasks"`. Word order differs between languages, so `"You have " + n + " tasks"` can't be translated.
- **Dates, times and numbers** are formatted by `Intl` (vue-i18n's `d()`/`n()`, or the calendar library's locale support) in the user's locale and time zone. The first day of the week follows the locale.
- **Layout** leaves room for text ~40% longer than English, and uses CSS logical properties (`margin-inline-start`) so right-to-left languages stay possible.
- **Lint** fails on hard-coded text in templates (`@intlify/eslint-plugin-vue-i18n`, `no-raw-text`), and `scripts/check-locales.mjs` fails if a locale is missing a key that `en` has, or has no `flag.svg`.

## Server
- The API sends **codes, not sentences** ([api.md](api.md#errors-rfc-9457-problemjson)). Their translations live under `errors.*` in the same files.
- Data the server creates for the user, like the default statuses "To do / Doing / Done" and the "Inbox" list, is named in the user's `locale` at sign-up, read from `locales/<code>/messages.json`.
- User content (task titles, notes) is never translated.
- Gotcha for later: Go's `//go:embed` can't read files outside the module folder (`server/`). `make gen` will copy the few keys the server needs into `server/internal/i18n/`, and CI will check that the copy is up to date.

## Apple apps (step 3)
A build script converts `locales/*/messages.json` into an Xcode **String Catalog** (`.xcstrings`, also JSON), reusing the same keys.

## Docs
Written in English first. Translations are separate files in a mirrored tree: `README.<code>.md` at the root (GitHub only renders `README.md` by default) and `docs/<code>/…` for the rest, with a language switcher line at the top of each file. Each translated file records the English commit it was translated from (`<!-- source: <sha> -->`) so stale translations are easy to find. To keep docs easy to translate: short sentences, no idioms or puns, no text inside images, code and commands kept identical.
