# daybook docs

> A living build log and portfolio write-up. Every milestone adds a chapter covering what was built, the concepts behind it, and the mistakes along the way. It's written so that someone new to the topic (including me, months from now) can follow it.

1. **[What daybook is](product/vision.md)**: the idea and the roadmap.
2. **[Architecture overview](architecture/overview.md)**: the big picture, and the life of one request.
3. **[Decisions](decisions/README.md)**: why things are built the way they are.
4. **[Steps](steps/1-planner/README.md)**: the build log, one chapter per milestone. Each chapter can be read on its own.
5. **[Concepts](concepts/README.md)**: short explanations that the other pages link to.
